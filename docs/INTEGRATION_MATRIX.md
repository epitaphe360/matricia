## Gaps prioritaires confirmés dans le code

1. **P0 release — signature réelle** : le mock est désormais impossible en production, mais le fournisseur contractuel, ses webhooks et sa certification restent à valider avant activation.
2. **P1 preuve d'environnement** : branche/SHA Vercel et readiness ont été vérifiés; worker Railway, ClamAV, SMTP Auth et fournisseurs sandbox restent à prouver à distance. Une présence dans `.env.example` n'est pas une configuration.
3. **P1 outbox** : la destination générique est maintenant explicitement un consommateur terminal d'observabilité sans payload; les effets métier dédiés doivent conserver leurs consommateurs propres et la chaîne distante reste à tester.
4. **P1 — email/Resend** : adaptateur natif implémenté et testé; la preuve de remise réelle et le SMTP Auth Supabase restent des validations distantes distinctes.
5. **P1 — contact support** : le formulaire persiste correctement, ne ment pas sur l'envoi et raccorde une notification support idempotente lorsqu'une adresse est configurée; la remise distante reste à prouver.
6. **P1 — IA** : l'orchestrateur générique est exploitable; `OPENAI_API_KEY` n'est pas consommé directement. Ne pas déclarer OpenAI activé sans configuration du provider générique ou adaptateur explicite.
