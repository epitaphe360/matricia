## Anomalie de transport découverte et corrigée pendant la recette

`0342_client_quote_exact_transport_acceptance.test.sql` reproduisait réellement un défaut supplémentaire : une ligne native de `9007199254740993` unités mineures était exacte en base, mais `compare_quotes` renvoyait des nombres JSON. Le sous-total impair `9007199254742193` ne pouvait donc pas traverser `JSON.parse` sans perte ; le contrôle TypeScript des entiers sûrs refusait correctement cette réponse. Avant correction, l’assertion du type texte échouait (`number` reçu, `string` attendu).

La migration `20261102035000` convertit quatre montants en texte uniquement dans les réponses. Le rédacteur canonique continue de calculer et conserver le snapshot, son hash et sa réponse d’idempotence d’origine. Le lecteur `get_client_quote_comparison_exact_v1` est `SECURITY INVOKER` : il retourne une copie de la dernière comparaison autorisée par la RLS. L’adaptateur Client utilise ce lecteur. Les vérifications TypeScript ne sont pas assouplies.

Après correction, `0342` réussit **30 assertions**, dont les chiffres impairs au-delà de `2^53`, les réponses du rédacteur et du lecteur, le hash brut toujours vérifiable, le cache inchangé, le refus d’accès aux autres organisations/prestataires, le rejeu et la sélection réelle du devis depuis le même snapshot. Les **9 tests unitaires ciblés** du transport et du repository réussissent, notamment le maintien du refus d’un nombre JavaScript non sûr. La revue indépendante de code n’a identifié aucun nouveau contournement concret de RLS, habilitation, idempotence ou hash ; elle ne constitue pas une exécution indépendante des tests SQL.
