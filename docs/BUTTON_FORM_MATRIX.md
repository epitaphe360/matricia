## États à valider dans les tests runtime

Pour chaque action métier : préconditions, validation serveur, chargement, désactivation, succès réel, erreur métier/réseau/serveur, retry, double clic/idempotence, retour arrière, expiration de session, rôle et organisation incorrects, clavier/focus, FR, AR/RTL et mobile. Le présent scan ne déduit pas ces états et ne les marque donc pas implicitement PASS.

## Limites du scan

- Les composants qui rendent indirectement une interaction et les éléments créés par une fonction factory peuvent nécessiter une revue AST/runtime complémentaire.
- La présence d'un chemin dans un test parent établit une référence, pas une assertion sur chaque bouton.
- Les handlers attachés par propagation de props peuvent apparaître comme expressions dynamiques ; leur action doit être rapprochée du composant parent.
