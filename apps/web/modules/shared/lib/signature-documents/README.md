# Documents sources contractuels FR/AR

Les routes authentifiées `GET /api/signatures/contracts/{contractId}/documents?locale=fr|ar&contractVersionId={versionId}` et `GET /api/signatures/amendments/{amendmentId}/documents?locale=fr|ar` rendent les sources figées. Le paramètre de version est recommandé pour les historiques. Réponse PDF privée `no-store`, nom `contract-source-…pdf` / `amendment-source-…pdf`, en-tête `X-Matricia-Document-Kind: UNSIGNED_SOURCE_DOCUMENT`. Ce fichier n’est ni un certificat de signature ni le document signé renvoyé par un prestataire.

La source SQL est recomposée depuis les manifestes de génération approuvée (258000), les refresh append-only et leurs réponses indépendantes (258040/258050), puis, le cas échéant, une chaîne réelle d’avenants activés. Aucun fallback depuis un contrat JSON ancien ou un hash fourni par le navigateur. Les prix, taxes, quantités, clauses FR/AR, règles de commission, parties et livrables proviennent des versions immuables. Les variations d’avenant restent distinctes des lignes du devis d’origine. Les montants utilisent des chaînes et BigInt. Aucune traduction de clauses manquantes ou nouvelle règle fiscale n’est inventée.

Le backend vérifie les droits avant de créer un client privilégié. Il génère les deux langues avec polices embarquées et date source fixe, charge sans écrasement dans `signature-source-documents` (privé, PDF, 20 MiB maximum), télécharge les octets réels et compare taille, en-tête PDF et SHA-256. Un conflit409 ne vaut succès qu’après cette relecture. La paire FR/AR est enregistrée atomiquement par RPC service-only avec source/parties/path/objets/tailles exacts et audit dédupliqué. Une paire incomplète, un upload échoué, un readback altéré ou un retrait des droits refuse le résultat. Les droits/session sont revérifiés après l’I/O ; aucune URL publique ni snapshot juridique n’est journalisé. Les RPC sont bornées5s et le transport privilégié10s par requête. Le collecteur PDF interrompt la sortie au-delà20MiB.

Les artefacts existants restent immuables et sont relus sans appliquer le moteur, les identités ou la politique actuelle. La preuve canonique et le hash PDF sont distincts. Les anciens artefacts sans langue ne sont jamais requalifiés automatiquement. Les bindings de signatures historiques ne changent pas de schéma/hash. Un envoi réel exige la paire FR/AR privée vérifiée et le PDF exact déclaré dans l’enveloppe. Le mock SIMPLE gouverné DEV/STAGING conserve son caractère explicitement non contractuel.

## Validation et limites

`0241_signature_canonical_source_archives.test.sql` utilise une vraie sélection et génération approuvée, avec classification fiscale publiée et revue indépendante ; vérifie source/ACL/pair/immutabilité/idempotence/stockage privé en transaction rollback. Ses objets Storage sont explicitement des métadonnées de fixture, pas une preuve de lecture de fichiers. Les tests TypeScript produisent de vrais PDF FR/AR reproductibles avec polices et vérifient les erreurs d’upload/readback/droits sur doubles de transport. Le test opt-in `storage.local.test.ts` a aussi été exécuté contre le véritable Storage local Matricia (loopback54321 uniquement) : PDFFR/AR réels, upload sans écrasement, conflit409, relecture exacte/SHA, refusURLpublique et suppression vérifiée des deux chemins UUID uniques. Aucune registration métier canonique ni signature n’est revendiquée par ce contrôle de transport. Une recette native HTTP/Supabase complète doit encore vérifier les routes authentifiées et l’enregistrement de paire sur le parcours canonique ; elle doit être rapportée séparément.

Aucun fournisseur certifié, niveau légal, certificat, timestamp externe ou fichier signé n’est inventé. L’activation réelle conserve les prérequis de politique gouvernée et de prestataire approuvé. Aucun envoi externe ni déploiement n’a lieu lors de ces validations.
